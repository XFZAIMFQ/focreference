采样时间

电流环页根据连续时间被控对象来整定增益；时序与同步页则计入了从电流采样到电压生效之间的传输延迟。但两者都还没有涉及第三件事：控制器本身是一个差分方程，而将连续积分转化为离散累加的具体方式，会改变环路的相位。

本页讨论这一差异的重要性，其答案颇为有趣：看似令人担忧的数值，实际上并非关键所在。

积分求和的三种方式

它们唯一的区别在于使用误差的哪个采样值。

方法更新公式
前向欧拉法uk​=uk−1​+Tek−1​上一步的误差
后向欧拉法uk​=uk−1​+Tek​这一步的误差
Tustinuk​=uk−1​+2T​(ek​+ek−1​)两者的平均值

前向欧拉法是大家最先写出的，因为循环天然就会累加刚刚计算得到的误差。

它们相对于理想积分器的相位恰好为 ±ωT/2:

频率前向欧拉后向欧拉Tustin
100 Hz−1.13°+1.13°0°
500 Hz−5.63°+5.63°0°
1000 Hz−11.3°+11.3°0°
2000 Hz−22.5°+22.5°0°

在16 kHz环路、1 kHz带宽下，11度看起来像是为了一个下标的选择而牺牲了相当大的相位裕度。

事实并非如此，原因如下

相位裕度是在穿越频率处评估的，而在穿越频率处，PI 控制器主要由比例项主导。积分项的比重——以及它所带来的离散化相位误差——恰恰在评估稳定裕度的频点处很小。

运行整个控制器，而不是仅运行积分器：

穿越频率连续 PI前向欧拉法相位损失
500 Hz−27.95°−29.16°1.21°
1000 Hz−14.86°−15.44°0.59°
2000 Hz−7.56°−7.56°0.00°

在设计点处，整个 PI 控制器的相位损失还不到 1°，而单独看积分器时则是 11°。离散化误差在积分器占主导的低频段（远低于穿越频率）最大，而在决定相位裕度的穿越频率处几乎不可见。

在实验台上 相位并非离散化影响的唯一特性，另一项效应反而更容易在实际测试中被察觉：在穿越频率处，前向欧拉法的幅值增益约偏低 5%，后向欧拉法则偏高约 5%，因此实际穿越频率也会随之偏移相近的比例。Tustin 法的幅值偏差则不到 0.1%。

因此，台架测试得到的带宽与设计值相差 5%，并不一定意味着测量有误或电机参数错误。很可能只是积分环节的问题，在重新辨识其他参数之前，有必要先排除这一可能性。

真正让你损失裕量的是什么

真正吃掉相位裕度的是传输延迟：单次更新 PWM 存在 1.5 个周期的延迟，在 16 kHz 环路、1 kHz 带宽下，相位滞后达 ωc​Td​ = 33.75°。

这是同一次采样过程中积分器离散化相位误差的五十倍。两者虽然都源于环路的离散特性，但只有传输延迟这一项值得在工程上设法应对。如果电流环出现振荡，先检查 PWM 比较寄存器的更新装载时序，再去看积分器算法。

混叠是第三项因素，且不是靠滤波器能解决的问题

采样并不会滤除高于半采样率的频率成分，而是将其搬移：高于奈奎斯特频率的分量会折叠回低频段，变得与真实的低频信号无法区分。采样器之后的任何数字滤波器都无法逆转这一过程，因为此时真假信号已经混在一起，无从区分了。

这听起来像是一个问题，因为驱动器的电流中存在与 PWM 频率完全一致的开关纹波——直到你注意到该纹波的具体位置：

alias(16kHz,16kHz)=0 Hz

与载波同步采样会将开关纹波精确折叠到 DC（直流）上，使其变成一个恒定偏置而非交变干扰；而在零矢量窗口中心采样——即电流采样页所安排的采样时刻——则能使这一恒定偏置恰好为零。

这就是为什么采样触发信号来自调制器自身的比较通道，而不是由软件 配置的定时器产生的。这并非出于方便或抖动的考虑；而是因为只有同步采样 才能使纹波消失，而不至于以其他形式显现出来。

只要稍微有一点偏差，你就能看出系统在为你做了些什么。 以 16.1 kHz 的频率对 16 kHz 的载波进行采样时，纹波会作为测量电流中的一个 100 Hz 分量重新出现——这是一种任何滤波器都无法消除的拍频，因为在采样之后， 对于下游的任何环节来说，它就是一个真实的 100 Hz 信号。

要点回顾

  • 积分器的三种离散化方法，相位上相差 ±ωT/2。 Tustin 方法是精确的；前向欧拉法滞后；后向欧拉法超前。
  • 在穿越频率处比例项占主导，因此整个环路的相位损失不到 1°，而单独积分器则相差 11°。那个看似惊人的数字，其实出现在无关紧要的频段。
  • 离散化确实会使穿越频率处的增益偏移约 5%，进而移动实际穿越频率。在怀疑测量不准或电机参数有误之前，请先排除这一因素。
  • 在同一工况下，传输延迟会造成33.75°的相位滞后。这是需要通过工程手段加以克服的离散化效应。
  • 混叠只是将信号搬移，并非将其消除。若与载波同步采样，开关纹波会被折叠至直流分量——这正是触发器应归属调制器而非软件模块的真正原因。
